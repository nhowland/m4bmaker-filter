Filter feature · mockup for ADR-0055 (Proposed)

Backing up and sharing your Word List

A working prototype of the Export/Import flow proposed in docs/adr/0055-catalog-import-export.md: choose what to export, and — the screen with the real information density — see exactly what an import would do before anything is written, with duplicates safely skipped by default.

Plan at a glance

Export scope
Everything, selected categories, or selected profiles — chosen in the dialog, not three separate buttons. Archived items only travel with "Everything," and only if opted in.
Category matching
Case-insensitive name match merges into an existing category; no match creates a new one. Restoring your own backup merges back into place; someone else's "Profanity" list joins yours instead of forking.
Duplicate policy
Skip by default — never silently overwritten. An explicit "Overwrite duplicates" checkbox opts in, off by default, per ADR-0054's lesson that this catalog is real manual effort, not disposable fixture data.
Before you commit
A preview shows exact counts and the full detail list — new categories, new words, duplicates (and what happens to them) — before the one explicit Import button.
Safety net
A timestamped backup of catalog.json is written just before the import's merged result is saved — same pattern as ADR-0054's unreadable-file backup, generalized to any risky bulk write.

Try it below — click Export… to see the scope picker, or Import… to try one of three demo files (a clean share, your own backup, and a corrupted one).

Trade-offs worth flagging

  • Skip-by-default breaks from ADR-0040's precedent on purpose. The Word List's manual "+ Word" flow rejects a duplicate outright; import instead skips it silently-but-visibly (shown in the preview, not hidden). Rejecting the whole import over one duplicate word would defeat the point of merging two lists; overwriting by default risks losing a real local edit exactly the way ADR-0054 happened. Skip-and-show is the only option that's both safe and still useful.
  • Re-importing your own backup should be a safe no-op. Try "my-backup.json" — every category matches by name, every word is a duplicate, the profile name matches. With nothing checked, pressing Import does functionally nothing (and says so) rather than silently duplicating everything or erroring out. This is the same shape of mistake that caused ADR-0054, deliberately re-created here against the fix to confirm the default is actually safe.
  • The preview groups by category, not one flat list. "shared-list.json" creates a new "Slang" category, merges words into your existing "Profanity" and "Religious," and brings one profile — grouping makes it legible at a glance which of those three things is actually happening to each word, instead of a Contributor having to infer it from a flat table.
  • The "Overwrite duplicates" checkbox is live, not just a flag read at Import time. Toggling it in the mockup relabels every duplicate pill and the count strip immediately — a Contributor should see exactly what they're opting into before pressing Import, not discover it afterward.
  • Not shown here: the real native pickers. QFileDialog.getOpenFileName/getSaveFileName (the same calls source_step.py and render_step.py already use) replace the "pick a demo file" list and the "Export…" button's save step — those are the OS's own dialogs, not something to mock.
  • Where the buttons live. Considered a menu bar (CatalogWindow has never had one) — rejected for two buttons; a top row next to the status label costs one row of height and needs no new chrome pattern the rest of the window doesn't already have.
